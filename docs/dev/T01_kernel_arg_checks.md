# T01: Kernel argument checks for every Python launcher

Status: todo
Executor: Claude (small, but the fixes need care about buffer meanings)
Depends on: T-1
Branch: `t01-kernel-arg-checks`

## Goal

Every Python script that launches a slabitz kernel directly must check its
argument list against the generated kernel table before launching. The
scripts that have fallen behind the current kernel signatures must be
brought up to date, and all of them must run from one pixi task. Today a
short argument list is not an error: `cuLaunchKernel` reads garbage
parameters, and the kernel may still "pass".

## Background (facts as of 2026-11-25, b506525)

- **The kernel table.** `src/sbz_kernels_gen.h` is generated by
  `tools/gen_kernel_table.py` and holds:
  - for each kernel, a `sbz_kparams_<Name>[]` array of
    `{ name, kind, elem_size, writable }`, where kind 0 is a buffer and
    kind 2 is a scalar;
  - `sbz_kernel_table[]`, with one row per kernel: name, cubin path,
    entry, workgroup size and parameter count.

  The C library checks every launch against it. The Python scripts do not.
- **Buffer convention.** A buffer argument is the struct `Buf { uint64
  data; uint64 count; }`, where `count` is in elements of `elem_size`
  bytes. The table entry `inCounters` has `elem_size` 88: one element is
  the whole counters struct.
- **PR #3 (da0452f)** fixed `bench/execute_bench.py`. It now passes 17
  arguments to ExecuteSequences. Remaining nit: `cb_cnt` counts u32 words
  for `inCompressedBlocks`, whose element is 16 bytes, so the count is 4x
  too large.
- **Scripts still short of arguments.** The P4 step 2b scalars (806b260)
  and the b840caa alias buffers left these behind:

  | Script | Kernel | Passes | Needs |
  |---|---|---|---|
  | `tests/run_exec_gpu_chain.py:119` | ExecuteSequences | 13 | 17 |
  | `tests/run_exec_multiblock.py:278` | ExecuteSequences | 13 | 17 |
  | `tests/run_frame_chain.py:185` | ExecuteSequences | 13 | 17 |
  | `tests/run_lit_gpu_chain.py:125` | InitHuffmanTableAndDecompressLiterals | 14 | 15 |

- **Scripts not in the test task.** 24 per-kernel scripts in `tests/` are

## Settled design

- **New `tests/kparams.py`** (importable from any cwd, like the other
  tests). It parses `src/sbz_kernels_gen.h` with a regex and needs no
  compiler. It provides:
  - `params(kernel)` returns the list of `(name, kind, elem_size,
    writable)`.
  - `info(kernel)` returns cubin path, entry, workgroup size and
    parameter count.
  - `check_args(kernel, args)` raises `AssertionError` naming the kernel
    and position when:
    - the count differs from the table;
    - a buffer position does not hold a `Buf`-like ctypes structure;
    - a scalar position does not hold a ctypes integer of `elem_size`
      bytes.

    It does not check buffer counts against data sizes, because a wrong
    count is not always detectable.
  - `python3 tests/kparams.py --self-test` parses all 22 kernels, checks
    that each parameter list length equals the table's count, and checks
    that a deliberately short list for ExecuteSequences raises.
- **Every per-kernel script** calls `kparams.check_args(...)` right before
  each launch.
- **Fixes.** Bring the six scripts up to date with the argument meanings
  used in `src/sbz_chain.c`. Fix the `cb_cnt` count in
  `bench/execute_bench.py`. Each script must still compare real output, and
  print what it compared.
- **Retiring a script.** A script that cannot be revived at reasonable cost
  (its stage no longer exists, or it duplicates a chain test) is retired:
  - its module docstring starts with `RETIRED (T01): <reason>`;
  - its launch code is left as it is;
  - the runner skips it and lists it as retired.
- **New `tests/run_kernel_scripts.sh` and pixi task `test-kernels`.** The
  script runs every non-retired per-kernel script, each under
  `timeout 300`. It passes the cubin path from `kparams.info()` under
  `${SLABITZ_KERNEL_DIR:-build}`. It prints one line per script (`PASS`,
  `FAIL` or `RETIRED`) and exits nonzero on any `FAIL`.
- **The test task.** Do not add `test-kernels` to `sbz test`; keep the
  two separate, since the per-kernel set is slower. AGENTS.md gets a rule:
  "run `sbz test-kernels` after any kernel signature change".

## Acceptance

Run on an idle GPU, after `CUDA_ARCH=sm_89 sbz build`.

1. `python3 tests/kparams.py --self-test` exits 0 and prints
   `22 kernels parsed, counts match`.
2. Every per-kernel launcher calls `check_args`:
   `grep -L "check_args" $(grep -l "cuLaunchKernel\|\.fn(\|fn(grid" tests/*.py bench/*.py)`
   prints nothing. (Files that do not launch kernels are excluded by the
   inner grep.)
3. `timeout 3600 sbz test-kernels` exits 0. Every line is `PASS` or
   `RETIRED`, there are at least 18 `PASS` lines, and each PASS script
   printed a nonzero compared count.
4. `CUDA_ARCH=sm_89 timeout 3600 sbz test` passes (11 scripts).
5. `python3 bench/execute_bench.py` (default settings) prints
   `verified=True`, or its equivalent, for every case.
