# T11b: GPU faults on corrupt Huffman, FSE and sequence data

Status: deferred (corrupt input only; do after T16. See "Check before deferral")
Executor: Claude (DS transform and kernels; not for the worker)
Depends on: T11 (`tests/run_gpu_corrupt.py`), T09 (frame bounds and status codes)
Branch: `t11b-gpu-faults`

## Goal

No corrupt compressed block may cause an illegal memory access on the GPU.
Every corrupt input returns an error code (normally CORRUPT with a frame
status) or decodes to some output. Today 11 of T11's 2008 inputs fault, and a
fault ends the process's use of the GPU (primary context).

## Background

- **T11 run after T09** (main bb081d1, seed 20261127, 2008 inputs; review
  section of `docs/dev/reports/T11.md`): canary-hit 0, crash 0, hang 0,
  gpu-fault 11. With `SLABITZ_DEBUG_SYNC=1`, the 11 split as:

  | where | count | inputs |
  |---|---:|---|
  | literals decoding (`chk:Literals`, InitHuffmanTableAndDecompressLiterals) | 5 | pac CeO2 u32 chunks (bit, ff, zero) |
  | sequence decoding (`chk:Sequences`, DecompressSequencesMultiStream) | 1 | pac silicon u16 (run8) |
  | stage 0/1, at the counter readback: ParseCompressedBlocks, FSE table init or Huffman weights | 5 | stock zstd text (run8) x2, pac x3 |

- **Reproducers**, one per row, committed in `tests/data/corrupt_faults/`
  (each with its `.json` sidecar, replayed by
  `python3 tests/run_gpu_corrupt.py --replay <file.bin>`):
  - `gpu-fault-2.bin`: literals;
  - `gpu-fault-1.bin`: sequences;
  - `gpu-fault-10.bin`: stage 1 (a 6.6 kB stock-zstd triple).

  The other 8 are regenerated by running the fuzzer with the default seed
  (saved under `build/corrupt_cases/`).
- **Likely causes, to confirm.** DS trusts sizes it reads from the block:
  - Huffman stream sizes and regenerated sizes (literals);
  - FSE table descriptions and accuracy logs (sequences, Huffman weights);
  - the number of sequences.

  An out-of-range value indexes past a table or a stream. T09's bounds cover
  only the output ranges and match offsets.

## Check before deferral (2026-11-28)

The user deferred T11b: corrupt input is rare in practice and the fix is
costly. Before deferring, each committed reproducer was replayed once under
`SLABITZ_DEBUG_SYNC=1 compute-sanitizer --tool memcheck --print-limit 10000`
(L40S, branch `t11a-literal-overread`, be43864). Each case has exactly one
memory violation, and it is a read; the other errors in the summary are
probably the 719 failure reported again by later API calls (not checked):

| reproducer | stage | violation |
|---|---|---|
| `gpu-fault-1.bin` | `chk:Sequences` | global read, 4 bytes, 14.7 GB past a 512-byte allocation (a wild index) |
| `gpu-fault-2.bin` | `chk:Literals` | 2x shared read, 4 bytes, address 0xffff9e98/0xffff9ea8 (negative shared index) |
| `gpu-fault-10.bin` | stage 1, `readback Counters` | global read, 4 bytes, 27369 bytes past a 4-byte allocation |

So no out-of-bounds write was observed. The kernel stops at its first fault,
so a write later in the same kernel cannot be ruled out, and the other 8
fuzz faults were not checked. Not mapped to source (nvdisasm): that stays
part of this task. The limit is recorded in `AGENTS.md` (known limits).

## Settled design

- Find each fault's load or store: replay under `compute-sanitizer --tool
  memcheck` with `SLABITZ_DEBUG_SYNC=1`, and map `main_0+0x...` to the source
  with `nvdisasm` (module `cuda/12.9.1`), as in T04a.
- **Fix with checks that set a per-frame status and stop the work item**, in
  the style of T09: status codes added to `zstdgpu_shared_structs.h` by the
  transform, the host naming them in the message. A check that only clamps an
  index so the access stays in bounds is acceptable where the output is then
  wrong but the frame already has a status.
- **Prefer checks outside the hot loops** (header and table parsing, once per
  stream or table). T04a and T09 showed that the per-match loop pays for every
  instruction. Any check inside literal or sequence decoding loops must pass
  the gate.
- **A corrupt frame may spoil other frames of the same call** through shared
  prefix sums (T11 review: frame 2 differed after frame 1 returned CORRUPT).
  That is allowed: the call fails and its output is undefined. Do not try to
  isolate frames' decode state.
