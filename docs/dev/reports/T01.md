## Reviewer checks (run by the executor; the reviewer reruns them)

- **`seqCapacity` deleted from `run_exec_gpu_chain`.** The script stops before launching:
  `AssertionError: ExecuteSequences: 16 args given, the kernel takes 17 (...)`. "launching" is not
  printed.
- **`inoutDecompressedSequenceOffs` (4-byte elements) and `inCounters` (88) swapped in
  `run_fso_gpu_chain`.** `check_args` passes, since both are buffers. The comparison catches it:
  `FAIL ... (1 seqs, 1 mismatch)`, and with `DSQ_MULTI=1`, `(7671 seqs, 7671 mismatch)`. Both
  print `compared 0` and exit 1.
- **RETIRED count:** 2 (limit 6).
  - `run_parse_blocks` only dumps buffers. `compare_parse_blocks.py` and
    `compare_parse_blocks_cases.py` import its `run()` and check each field against
    `kernels/cpu_ref_pcb.py`, so the launch still runs and is still checked.
  - `smoke_initfsetable` only checks that 64 elements were written. `compare_initfsetable`
    launches the same kernel and compares all 128 table elements of its cases with
    `kernels/cpu_ref_ifs.py`.
- **Extra: the runner's coverage guard.** With a temporary `tests/zz_unlisted.py` containing a
  `fn(grid=...)` call, the runner printed `FAIL zz_unlisted (launches a kernel but is not listed
  ...)` and exited 1. The file was removed afterwards.

## Decisions

- **Byte-address buffers.** `check_args` treats kind 1 (`SBZ_KP_BAB`, ByteAddressBuffer) as a
  buffer too. The task file named only kinds 0 and 2. Kind 1 is the same 16-byte
  `{data, size in bytes}` struct in CUDA; the literals and sequence kernels take
  `inCompressedData` that way.
- **The `compared N` convention.**
  - Every script the runner runs ends with a line `compared N <what>`. The runner requires exit
    0 and N > 0, so the AGENTS.md rule "a test that compares nothing must fail" is checked by
    machine, not by reading logs. N is 0 when the script failed.
  - `run_dsq_chain` and `run_seq_gpu_chain` used to `return 0` when the block had no sequence
    stream ("nothing to validate"). They now fail.
- **CPU-only scripts are in the runner.** These are `run_dsq_chain`, `run_e2e_chain`,
  `run_fso_chain` and `run_lit_chain`: the task's list of 24 includes them, and they cost
  under a second. They take no cubin.
- **Extra modes.** The default payload has one sequence, so `run_dsq_chain`, `run_fso_chain`
  and `run_seq_gpu_chain` compare a single sequence. The runner also runs
  - `DSQ_MULTI=1` (7671 sequences) for those three and for `run_e2e_chain`,
    `run_exec_gpu_chain` and `run_fso_gpu_chain`;
  - `DSQ_SEQMS=1`, with and without `DSQ_MULTI=1`: DecompressSequencesMultiStream with its 21
    arguments. The task file noted that this mode needed one more.

  Entry syntax: `script:kernel:ENV=VAL,...`.
- **`run_seq_gpu_chain`** chooses the kernel from `DSQ_SEQMS`. Its default cubin is that kernel's
  path from the table, and it adds `seqCapacity` for the multi-stream kernel.
- **Counts fixed while there.** `inCounters` counts are now 1 element of 88 bytes in the scripts
  I edited for other reasons; they were 24 (u32 words). The kernels read only element 0, so this
  changed no results.
- **`run_unshuffle_slow` and `run_unshuffle_warp`** got `check_args`. They are in `sbz test`, so
  the runner skips them (named in its `IN_SBZ_TEST`).

## Open issues

- `DSQ_RAW=1 python3 tests/run_e2e_chain.py` fails with `IndexError` on `main` too (line 120: the
  raw payload produces no compressed block). It is not in the runner. It predates T01 and is
  outside its scope.
- `gpu-run` asks Slurm for no memory, so a job gets the partition default. `exec_scaling.py` at
  16384 frames was OOM-killed on the host there. A `--mem` option for `gpu-run` would fix it
  (T-1 territory, T03 will need it for big batches).
- The runner prints per-script seconds from bash `SECONDS` (whole seconds); the total run time
  was not measured.
- Kernel sources are unchanged (same source key and `SBZ_KERNELS_ID`), so `build/sm_35` and
  `build/kernels` need no rebuild.
