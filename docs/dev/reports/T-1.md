## Decisions and deviations

- **Bootstrap.** Before this task merges, `main/` and `env/` are at `origin/t-1-agent-root`
  (recorded in `$ROOT/.main-ref`, used as the default ref by `dev-root`). After the merge run
  `echo origin/main > $ROOT/.main-ref && dev-root update-main`. `repo.git` was cloned from the
  local checkout; its `origin` is GitHub, so `update-main` fetches from GitHub.
- **Paths.** GPFS reports `/gpfs/gd/data/...`; crunch sees only `/data/...`. Per the user, `/gpfs/gd`
  is stripped everywhere: activation hooks, script shebangs in the env, worktree git links, `REPO`
  in `sbz.sh`. Re-run `dev-root update-env` if the env is reinstalled (it redoes this).
- **Activation hooks** are generated from `pixi shell-hook` but cleaned: only the env's own PATH
  entries (not the generating user's PATH), no `PIXI_*` variables, no `pixi()` function.
- **Workers must use relative paths.** opencode's guard treats an absolute path to the root as
  external (it resolves its cwd to the `/gpfs/gd` form). `AGENT_START.md` says so.
- **Publishing.** The first version did `chmod a-w` before `mv`, so the move failed and the set was
  silently dropped; fixed (move, then chmod, and failure is an error).
- **sm_35 builds** need `LD_LIBRARY_PATH` to include the kepler lib dir (NVRTC 11.8 loads its
  builtins by name); `sbz` sets it for that command only.
- **Extra files** not in the task's list: `tools/kernel_sources.py`, `tools/data_inventory.py`.
- **Real data:** also linked `eiger4m_u32.h5, big_eiger_0000.h5, kevlar.h5, hplc.h5,
  Calibration_Al2O3.h5` (all readable HDF5), the examples' `mask.h5`, `geometry.par` and README.

## Rerun 2026-11-27

Rows 2, 3 and 5 do not reproduce reliably. On the merged base (36cfab8), `gpu-run timeout 300
python3 tests/run_bslz4_device.py` failed "u8 8k: replays 1 (want 0)", with byte-correct output.
It failed in 6 of 7 runs on frcrg-gpu5l40s-01 (driver 580.178.04), and it only fails after the
u16, u32 and u64 cases have run in the same context. The decoder flagged chunks 2-4 with
status 1, i.e. the end of the input, and the walk passed. The cause is a race in the test, not in
the library:
- `cuMemcpyHtoD` from pageable memory can return before its DMA lands.
- The context's stream is non-blocking, so it does not wait for that copy.

The earlier passes were timing luck. Fix: `cuCtxSynchronize()` after the upload in the test (and
in `bench/p4_overlap.py`), and the precondition stated in `src/sbz_chain.h`. With the fix:
8/8 runs of the test pass, and the full `gpu-run timeout 590 sbz test` on 36cfab8 plus the fix
gives rc=0, "sbz test: all passed" (u8 8k: replays 0, 2000000 B match). Its `build/sm_35` and
`build/kernels` id checks print "skip (not built)", so they did not run.
