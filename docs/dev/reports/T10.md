# T10: Decoder: frames without a content size (part 1, bitshuffle chunks)

Status: review
Branch: `t10-no-fcs` (on `t11b-deferred`)
Executor: Claude

## Result

- **Bitshuffle-zstd chunks whose frames have no Frame_Content_Size now
  decode.** Each frame takes its size from the chunk: the block size times
  the element size, or the last block's size.
- **Part 2 is deferred**, as the user decided on 2026-11-28: plain `.zst`
  streams without an FCS (`sbz_dctx_decompress`, `_frames`), the
  `sbz_dctx_frame_sizes` call and the `run_compat` no-FCS cells. Those
  streams still return UNSUPPORTED "frame N: no content size".
- **No new readback, and no change to the hot loops.**

## How

- **Trace (step 1 of the settled design).**
  - The frame bases and sizes the GPU uses come only from the host, in
    `UnCompressedFramesRefs` (`stage2` in `src/sbz_chain.c`).
  - ComputeDestBlockOffsets checks each block's decoded size against those
    refs (T09). The sizes come from `inBlockSizePrefix`, which holds the
    decoded block sizes computed on the device.
  - The GPU frame parser's own content size feeds only the request-size
    counter, and the host checks the 1 GiB limit itself (`host_prepare`).
  - So for a frame without an FCS, the host only has to supply the size. This
    agrees with the settled design.
- **Host walk** (`src/host_walk.c`):
  - a frame without an FCS is no longer rejected; it is flagged
    `noContentSize`;
  - its `uncompSize` becomes an upper bound: raw bytes, plus RLE bytes, plus
    Block_Maximum_Size for each compressed block.
- **`host_prepare`** takes the sizes the caller expects:
  - a flagged frame takes its expected size, or gets CORRUPT if its bound is
    smaller;
  - with no expected sizes (the plain path), it returns UNSUPPORTED as
    before.
- **Transform patch `NO_FCS_PATCHES`:** `zstdgpu_FrameStatusFromHeader` no
  longer returns MissingContentSize. That status is now unused.
- **On the GPU:** a frame whose blocks decode longer or shorter than the
  expected size gets the T09 status 0xA07A0007 (past) or 0xA07A0008 (short),
  and the call returns CORRUPT.

## Size

Recompressing a chunk without FCS saved 74 bytes on 129,842: 1 byte per
8 kB frame. A frame without an FCS cannot be single-segment, so it needs a
Window_Descriptor byte, which cancels most of the saving. The user's question
was about the compression ratio of all-zero frames, and the crossover between
sparse and bitshuffle-zstd storage. The decoder now accepts such chunks, so
the choice is open.
