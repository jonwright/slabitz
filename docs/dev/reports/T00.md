## What was built

`tools/synth/` (numpy, h5py, hdf5plugin; libpac and the educational decoder
for P4):

- **Model: fitted, not hand-tuned.** `fit` reads 12 frames spread over each real
  file and stores, in `params/<key>.json` + `.npz` (2.3 MB in all):
  - the exact mask: pixels holding the same masked value in every frame. For
    silicon and ceo2 it comes from the `*_lz4mask.h5` twins of the files, since a
    sparse plain file cannot tell a gap from an empty pixel;
  - a coarse map of the expected count: block means with hot pixels left out,
    adaptively smoothed to at least 800 counts per block;
  - per fitted frame, a ratio map on 32-pixel blocks: that frame's block sums
    over what the map expects. Scans change brightness and move the pattern
    between frames;
  - a mean-one gamma shape per range of expected count (Poisson-gamma counts);
  - the tail:
    - an empirical sample of the values above the clip;
    - how many each fitted frame holds;
    - how they cluster: consecutive values of the sorted sample form a cluster
      of a few pixels with the biggest at the centre, so bright pixels sit with
      bright pixels;
    - where they are: a coarse density map.
- `twin.frames` is a pure function of (params, seed, frame index). Twin frame i
  uses the ratio map and hot count of fitted frame i modulo 12. Extensions
  resample the same pattern to another detector size, element type, mask value
  and brightness.
- `metrics.py`:
  - **P1:** class fractions of live pixels, mean up to the clip, hot fraction,
    masked fraction, log-histogram JSD.
  - **P3:** zero and equal-to-previous planes after bitshuffle, at 8 kB and
    256 kB. Up to 2048 blocks spread evenly over all frames and positions.
  - **P4 ratios:** hdf5plugin LZ4 8 kB, zstd 2 and 3 at 256 kB, pac LZ4 and
    zstd.
  - **P4 zstd byte classes**, from the educational-decoder dump of 128 blocks
    spread over all frames:
    - RLE/raw bytes, counted over every block;
    - then, as fractions of the bytes in compressed blocks: literals, copies of
      zero bytes, and copies of data split by offset (1 = fill, 2-15 = short and
      overlapping, 16 and more = long).
- `worst.py`, `zstdlib.py`:
  - Worst cases are built in "stream space", i.e. what the entropy coder sees
    after the transpose. `unshuffle` inverts it, checked against hdf5plugin for
    u8..u64.
  - A zstd header analyser and a small frame writer, so Huffman literals with a
    chosen code, treeless and zero-sequence blocks, and an exact 131072-byte
    block are hand-built.
- `ext.py`, `cli.py`, `gpu_time.py`; `tests/run_synth_decode.py` (rewritten: it
  decodes through slabitz on the GPU).

Output in `data/synth/v2/` (3.8 GB, 263 files, read-only, `current -> v2`):
- `twins/<key>/`: 16 frames, raw.npy plus encodings. For silicon and ceo2 the
  mask is written both as 0 and as 2^n-1.
- `ext/`: 36 entries.
- `worst/`: 24 cases.
- Each with `manifest.json`.

`data/synth/v1` (generator version 1) is kept, read-only, for comparison; it
can be deleted.

`tests/data/synth/`: 33 files, 1.70 MB, with `MANIFEST.json` (sha256 of the
decoded bytes).

## Changes from version 1

Version 1 failed 23 of 215 compare checks. Each change below is backed by a
measurement on the real files:

- **zstd byte fractions were measured wrong.**
  - "literal" was the block size minus match bytes, so RLE blocks (the all-zero
    high planes) counted as literals. eiger4m_u32's 0.50 against 0.125 was just
    how many of the 8 sampled zstd blocks were RLE; with them excluded, both
    are 0.001.
  - The sample was the first 4 blocks of frame 0. Two random 48-block samples
    of the same real file differed in off=P by up to 0.09.
  - The copies of zero bytes carry all the remaining real-twin differences:
    data copies agree (zstd2 long data copies, real / twin: ceo2 0.040 / 0.036,
    al2o3 0.065 / 0.063, silicon 0.027 / 0.033).
  - Any earlier zero byte can serve as the source of a zero copy, and libzstd
    picks the offset from its repeat-offset history. So the offset split of
    zero copies (and off=P) is printed, not checked.
- **kevlar's pattern changes during the scan.** One map averaged over 12 frames
  could not reproduce the frames. The per-frame ratio maps fix all its classes
  (for example class 16-255: 0.0012, now 0.0025, against real 0.0026).
- **silicon's bright hot pixels were spread over too many blocks.** Version 1
  gave every cluster one of the top values. With bright values kept together,
  P3 zero planes at 256k is 0.837 against 0.839 (version 1: 0.764).
- **P3 sampled the same detector region in every frame.** It took a fixed
  stride per frame and 64 blocks; it now spreads up to 2048 blocks over all
  frames and positions.

## Acceptance

### 1. Twins match their real files: NOT fully met (250 of 256 checks)

Command: `python3 -m tools.synth compare --all`. It uses the 12 fitted frames,
so it tests the model, not generalisation; al2o3 has only 10 frames.
- 250 checks pass and 6 fail.
- 5 of the 8 keys pass every check: silicon, ceo2, thaumatin, big_eiger, kevlar.
- Every compression ratio passes (40 of 40 within 10%).
- Every P3 check passes except al2o3 at 256k.

| key | failing check | twin / real |
|---|---|---|
| eiger4m_u32 | P4 zero-copy fraction, zstd 3 | 0.262 / 0.318 (zstd 2 passes: 0.271 / 0.310) |
| eiger4m_u32 | P4 long data-copy fraction, zstd 3 | 0.723 / 0.668 (zstd 2 passes: 0.714 / 0.676) |
| hplc | P1 class 2-3 | 0.0266 / 0.0236 (13% against 10%) |
| al2o3 | P1 class 4-15 | 0.138 / 0.108 |
| al2o3 | P1 JSD | 0.055 (at most 0.05) |
| al2o3 | P3 zero planes 256k | 0.772 / 0.674 |

- **eiger4m_u32:**
  - Zero copies plus long copies are 0.985 in both twin and real; the split
    between the two misses by 0.006 at zstd 3 only.
  - The split depends on whether libzstd extends a zero run across an isolated
    non-zero byte or breaks it there. That depends on how the single counts are
    arranged, which the twin draws independently per pixel.
  - Not investigated further.
- **hplc:** class 2-3 not investigated.
- **al2o3** is a powder calibrant: thin rings and grains in the same place in
  every frame.
  - An 8-pixel map blurs them.
  - A 2-pixel map fixed class 4-15 in a trial (0.112 against 0.108). But the
    0.05% of pixels with counts 256-4095 carry about a sixth of the mean, and
    the twin places its bright spots elsewhere.
  - Matching it would need a per-pixel mean image plus the real spot
    positions, i.e. resampling the real image. Not done.
  - The file's own `mask` dataset was checked against the fitted mask. All
    250,824 masked pixels are in the fitted mask, which adds 3,232 pixels that
    are 0 in all 10 frames. That is not the cause.

### 5. Decoding: met

Command: `gpu-run python3 tests/run_synth_decode.py` (also in `sbz test`).
- The 33 committed files go through the GPU, all byte-exact. The no-FCS frame
  is rejected (rc -5), and the CUDA context stays usable after the rejection.
- With `SLABITZ_SYNTH=$SLABITZ_DEV_ROOT/data/synth/v2`: all of v2,
  6,109,415,678 bytes compared, all passed.
- The same run on v1 also passes.
- The CLI-written worst frames use `--stream-size` (stdin gives no FCS
  otherwise).

Findings about the decoder, for T09/T10 and not fixed here:
- The decoder accepts all the hand-built frames: 11-bit Huffman, treeless,
  maximum-accuracy FSE tables, the exact 131072-byte block, 0-sequence blocks.
- A rejected frame leaves the context unusable: every later call returns
  SBZ_ERR_ARGS. So the test makes a new context after any failure and runs
  expected rejects in a subprocess.
- Once, in-process, creating a context right after the no-FCS rejection failed
  with CUDA error 700. In a fresh process the context was usable after the same
  rejection. Not reproduced since.

## Decisions

- Mask first: the mask is stored exactly (it is detector geometry); everything
  else is fitted.
- "Hot" is defined by the model's clip (99.99th percentile of live values), so
  the P1 mean compares the part the map models. The raw mean is printed but is
  not a check: on silicon a few hundred pixels per frame carry much of it. This
  replaces "mean within 5%".
- P4 fractions check RLE/raw bytes, literals, zero copies and the offset split
  of data copies. The offset split of zero copies and off=P are reported only
  (see "Changes from version 1"). This replaces the literal / off=1 / off=P
  fractions.
- Compare uses the frames the fit used, so it tests the model, not held-out
  frames.
- `pixi.toml` was not changed; the regression list is `cmd_test` in `tools/sbz.sh`.
