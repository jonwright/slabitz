3. **`5edab27` generator + fixtures.** `tools/gen_pac_fixtures.py` encodes
   detector frames (cropped to a contiguous row range, full row width) with
   libpac.so into filter-32008 chunks, one per frame, and writes
   `data/pac/<case>.chunk.bin` (concatenated), `<case>.index` and `<case>.json`
   (elem size, block bytes, per-frame source/crop/mask, SHA-256 of each decoded
   frame, pac version and commit). The expected output is stored only as a hash,
   so the repository stays small.
4. **`a55dd36` run_pac_fixtures + sbz entry.** `tests/run_pac_fixtures.py`
   decodes every fixture with `sbz_dctx_bshuf_decompress` /
   `sbz_dctx_bslz4_decompress` (sync and async) and compares the SHA-256 of each
   decoded frame against `<case>.json`; the same chunks are decoded on the CPU
   with hdf5plugin and compared with the same hash. `--stats` walks each zstd
   frame with `tools/edu_oracle.py` and counts the SEQ fast paths. Added to
   `cmd_test` in `tools/sbz.sh`, so `sbz test` and the pytest entry point run it.
5. `docs/dev/reports/T02.md` (this file) + status updates.

## Decisions

1. **Lists parsed, not duplicated.** `tests/test_suite.py` derives the test set
   from `tools/sbz.sh` `cmd_test` (`run_t tests/*.py`) and
   `tests/run_kernel_scripts.sh` SCRIPTS, so the pytest entry cannot drift from
   `sbz test` / `sbz test-kernels`.
2. **`slow` set (measured once on the login-node L40S):** `run_chain_stage01`
   (196 s), `run_chain_stage2` (242 s). Every other script is well under 60 s
   (run_synth_decode 32 s, run_bslz4_chain 16 s, run_host_walk 8 s,
   run_pac_fixtures 3 s, the kernel scripts <= 1 s).
3. **`gpu` marker.** All `sbz test` scripts create a CUDA context
   (`sbz_dctx_create_cuda`), so all are `gpu`. In `sbz test-kernels` a script is
   `gpu` iff its SCRIPTS entry has a non-`-` kernel (it launches a kernel); the
   CPU-only scripts (`kernel = "-"`) are run_dsq_chain, run_e2e_chain,
   run_fso_chain and run_lit_chain (the ones T01's report calls CPU-only), and
   those same scripts' DSQ_MULTI modes stay CPU-only. 35 gpu / 7 non-gpu of 42.
4. **`SLABITZ_REQUIRE_DATA=1` in the pytest child:** set only when
   `SLABITZ_EXAMPLES` is set. A fresh clone (no `SLABITZ_EXAMPLES`) still skips
   instead of failing.
5. **pac block sizes:** pac's recommended defaults, recorded per case:
   253952 (zstd) and 57344 (lz4). They are not a multiple of 64 kB (pac's note:
   bit planes whose length is a multiple of 4096 bytes make the transpose slow),
   and the plane byte count P = block_bytes/(8*elem) is what the fast paths need.
6. **Multi-frame fixtures:** several frames per case (2 or 3), concatenated in
   `*.chunk.bin` and addressed by `*.index`, so the decode call exercises the
   multi-frame path (one call, N spans) as well as single frames.
7. **The all-zero (RLE) case and the three-column rule.** pac encodes an all-zero
   frame as a single RLE block: there are no zstd sequences, so `--stats` reports
   zero in all three columns. `--stats` enforces the three-column requirement
   only for zstd cases that contain sequences (it prints the all-zero case and
   marks it RLE-only).
8. **pac already writes LZ4 chunks** (verified), so the reviewer's LZ4-fallback
   is not needed; the LZ4 case uses `pac_compress_chunk` with `PAC_LZ4` and is
   decoded correctly by `sbz_dctx_bslz4_decompress` and hdf5plugin.
9. **Deviation — the mutation shape.** The reviewer's check said "take the byte
   fallback with a deliberate off-by-one". I instead kept the aligned vectorized
   copy and injected the off-by-one into its source index for merged matches
   (`srcOfs += (mlen > offs)`), which corrupts exactly the merged-match output.
   The effect on the check is the same (run_pac_fixtures fails), and it exercises
   the vectorized merged path rather than the byte loop.
10. **Compared-count audit.** Every `sbz test` script prints a compared count and
    fails when it is zero (integer checks like `FAIL ... case(s) failed`, the T01
    `compared N` convention, and run_pac_fixtures compares `total == 0` and
    `cpu_compared == 0`). No script needed fixing; `run_pac_fixtures.py` follows
    the convention.
