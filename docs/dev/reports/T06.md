## What was built

Two new test scripts plus oracle hook additions:

* `tests/run_features.py` - the feature matrix.  It builds a corpus (libzstd
  frames over many levels/params/data kinds, plus hand-built frames for the
  features libzstd will not emit), classifies every frame with the educational
  decoder, decodes each entry with `sbz_dctx_decompress`, compares byte-exact
  against `zstandard`, prints the matrix, and fails on any empty matrix cell
  or unexpected result.
* `tests/run_roundtrip.py` - the fixed-seed round trips (levels 1-19, sizes
  1 B to 4 MB on a log scale, six data kinds, single frames and concatenated
  batches), compared byte-exact against `zstandard`.
* `tools/edu_oracle.py` - four new dump-hook tags: `LITBLK` (literals-section
  type + size format), `LITSTREAM` (type + size format + stream count),
  `SEQMODES` (LL/OF/ML table modes + sequence count), `SEQCOUNT` (sequence
  count, including 0).  These drive the classifier.
* `tests/test_suite.py` - registers the two new scripts (run_features is now
  part of `sbz test`; run_roundtrip is under the `slow` marker).
* `tools/sbz.sh` - added `run_t tests/run_features.py` to `cmd_test`.

## xfails / decoder bugs

**One.**  `hand-dict-id-1` - a frame with a `Dictionary_ID` field (value 0).
This is a decoder bug, not out of scope: `zstandard` (libzstd) decodes it to
140 bytes, the host walker accepts it, but the GPU `ParseFrames` kernel
rejects it (`sbz_dctx_decompress` returns `SBZ_ERR_CORRUPT` (-5) with the
error "block counts GPU raw/rle/cmp 0/0/0 != host 1/0/0").  It carries
expectation `xfail:GPU ParseFrames rejects a frame with a Dictionary_ID field
(T09)`, is compared against libzstd's output (so it would XPASS once the bug
is fixed), and its reproducer is written to:

* `tests/data/features_bugs/did_field.zst` (150 bytes, the frame)
* `tests/data/features_bugs/README.txt` (one line: what fails, the error text,
  the task that should fix it - T09)

## Decisions taken

1. **Frame-header features are parsed in Python; block-level features come
   from the oracle hooks.**  The frame header (FCS size, single-segment,
   checksum, window, dictionary-ID) is a small, well-understood byte layout
   that `tests/run_host_walk.py` already parses; only the compressed-block
   internals (literals type/streams, table modes) need the educational
   decoder's hook tags.
2. **Hand-built 0-sequence blocks use RLE or raw *literals* sections.**  A
   compressed block with 0 sequences needs no sequence FSE bitstream (just a
   `0x00` count byte), so it is trivial to write correctly.  This avoids
   writing an FSE encoder.
3. **RLE literals, RLE frame block and raw frame block are hand-built** (the
   only cells libzstd will not emit).  RLE literals use size formats 1 and 3
   only: formats 0 and 2 share a degenerate 5-bit regenerated-size field that
   is not worth hand-encoding (those size formats are covered by libzstd).
4. **RLE-literals stays the single RLE-literals source** so the starve check
   is precise (see above).
5. **A single-pre-segment raw-literals 0-sequence block is rejected by
   libzstd**, so hand-built raw-literals 0-sequence frames are multi-block
   (the raw-literals block is not the last block) or non-single-segment.
6. **`hand-checksum-on` is not hand-built**: python-zstandard's `decompress`
   verifies the checksum, so a hand frame would need the real XXH64 bytes;
   the libzstd `write_checksum=True` corpus entries already supply the
   checksum-on cell.
7. **Matrix cells count only byte-exact decodes.**  In the first revision the
   `aggregate` was bumped from the classification of every entry before
   decoding, so a feature that appeared only in a rejected (or failing) entry
   would have been reported as covered.  Now `aggregate` is bumped only after
   the byte-exact compare succeeds; a separate `reject_agg` tallies the
   features of expected-reject entries and is printed as its own "(expected
   reject)" section.  Only `fcs_size=0` (a no-Frame_Content_Size frame, which
   the decoder rejects) may be satisfied by that tally (see the
   `ALLOWED_REJECT_CELLS` constant).
8. **No automatic xfails.**  A `decode` entry that does not decode byte-exact
   is an unexpected result (failure), not an xfail.  An `xfail:<reason>`
   entry is reported as xfail when rejected (with its reproducer path) and as
   XPASS (counted as unexpected) when it decodes byte-exact - so a regression
   that makes the decoder reject valid frames is caught, and so is the bug
   being fixed.
9. **A shared-context pass runs after the per-entry pass.:** one `dctx` is
   reused across the whole corpus (the realistic use), with the same
   expectations and byte-exact compare; any result that differs from the
   per-entry pass is an unexpected result naming the entry.  This catches
   context-reuse bugs (e.g. a filter state left over across inputs of
   different sizes/kinds).  Both passes' compared bytes are printed; the
   default runtime stays under 3 minutes (74 s).
10. **The level 15 img_u16 data and the token4 data** were chosen from probes
    (probe11/probe12) specifically because they alone drive the `ll_mode=3`
    (repeat LL), `ml_mode=1` (RLE ML), `size_format=3`, and `treeless/1`
    (1-stream treeless) cells.

### The development-time context crash

During development the per-entry pass first used ONE shared context.  The
crash came from the *then-malformed* `hand-rle-literals-sf0` entry: it
encoded an RLE-literals block with size format 0 (a 5-bit regenerated-size
field, max 31) but a declared size of 500, so the size was truncated to 20
bits' worth and the frame did not match its Frame_Content_Size of 500.  The
decoder read the undersized literal section and the GPU returned an illegal
memory access (`SBZ_ERR_BACKEND` on `cuStreamSynchronize`), which then
poisoned the shared context for every following entry ("previous async call
not waited for").  That entry was malformed at the time.  After the size-format
was corrected (the `hand-rle-literals` frames now use sizes that fit formats 1
and 3) and the per-entry pass switched to a fresh context per entry, the crash
is no longer reproducible with the final corpus: the reviewer's own run of the
shared-context pass reports all 366 entries passing.

## Notes

* The `hand-skippable-start` frame uses a zstd frame *after* the skippable
  frame: python-zstandard's single-shot `decompress()` does not accept a
  leading skippable frame, but the slabitz decoder does.  `run_features.py`
  strips leading skippable frames before asking libzstd for the expected
  output.
* The per-entry pass uses a fresh context per entry so that a crashing entry is
  isolated; the shared-context pass reuses one context to exercise the reuse
  path.  Both must produce identical results.
* Every statistic is deterministic: fixed seeds everywhere, no wall-clock
  dependence.
